Note on Storefront URLs

In production, you should not expose Stripe account IDs in URLs. Instead:

  • Create merchant profiles with proper database IDs
  • Map those IDs to Stripe account IDs server-side
  • Use URLs like: /shops/merchant-name or /shops/user-id

Step 5: Subscriptions

API Reference

Available Endpoints

  • POST /api/accounts - Create connected account
  • POST /api/onboarding/link - Get onboarding link
  • GET /api/accounts/:accountId/status - Check account status
  • POST /api/products - Create product
  • GET /api/products/:accountId - List products
  • POST /api/checkout - Create checkout session
  • POST /api/subscriptions - Create subscription
  • POST /api/billing-portal - Create billing portal session

Webhook Setup

Configure Webhooks

Set up these event listeners in your Stripe Dashboard:

  • customer.subscription.updated
  • customer.subscription.deleted
  • invoice.payment_succeeded
  • v2.account[requirements].updated (thin events)
  • v2.account[configuration.merchant].capability_status_updated (thin)

Webhook URL:

/webhook and /webhook/thin

Test with Stripe CLI:

stripe listen --events customer.subscription.updated,customer.subscription.deleted,invoice.payment_succeeded --forward-to localhost:3000/webhook
